# Решения и результаты проверок

Проверки P1–P4 из `SPEC.md` (раздел 11). Прогон: 2026-11-16, Claude Code 2.1.322, macOS 15.7, сессии запускались в pty через `scripts/fake-hud.py` (фейковый HUD) и тестовые настройки `--settings`.

## P1. Диалог в терминале, пока хук ждёт

**Разрешения (`PermissionRequest`).** Claude Code показывает свой диалог «Do you want to proceed?» в терминале **параллельно** с работающим хуком (строка статуса: «running PermissionRequest hooks… 1/2»). Через ~6 с приходит `Notification` с `notification_type: permission_prompt`.
- Ответ из HUD (`behavior: allow`) → диалог в терминале закрывается, инструмент выполняется.
- Ответ в терминале → инструмент выполняется, но **процесс хука не убивается**: он ждёт до своего дедлайна. Его поздний пустой вывод Claude игнорирует.
- Вывод: окошко в HUD снимается по следующему событию сессии (`PostToolUse` того же инструмента, `Stop`, `UserPromptSubmit`, `SessionEnd`), и приложение само отпускает висящий хук ответом `passthrough`. Так и реализовано в `SessionStore.apply` (возвращает id запросов для освобождения).

**Вопросы (`PreToolUse` на `AskUserQuestion`).** Пока хук держит вопрос, терминал **не показывает** вопрос — только спиннер «running PreToolUse hooks…».
- Ответ из HUD через `updatedInput.answers` → агент получил ровно выбранный вариант (проверено: выбор «Red» → агент создал `p2_Red.txt`).
- Вывод: в окошке вопроса обязательна кнопка «Ответить в терминале» (отпускает хук пустым выводом, вопрос сразу появляется в терминале).

## P2. Просрочка

Хук сам отпускает ожидание за 5 с до своего `timeout` и печатает пустой вывод.
- Вопрос: сразу после этого Claude показывает вопрос в терминале как обычно (проверено с `timeout 12`).
- Разрешение: диалог в терминале уже на экране, сессия продолжает его ждать.
- HUD при закрытии соединения после дедлайна помечает запрос как `expired` и показывает «Просрочено».

## P3. Переход в терминал

- `agenthud-hook` получает TTY агента через `sysctl` (без запуска процессов). В пробе: `/dev/ttys001`.
- **Процесс Claude Code называется номером версии** (`2.1.322`), а не `claude`. Поэтому агентом считается первый предок хука, который не оболочка (`HostProbe.agentProcess`).
- Внутри herdr доступны `HERDR_ENV=1`, `HERDR_PANE_ID`, `HERDR_SOCKET_PATH`; фокус — `herdr agent focus <pane_id>`.
- Terminal.app: AppleScript, поиск вкладки по `tty of tab`.

## P4. Подхват хуков открытыми сессиями

Владелец подтвердил, что уже открытые сессии подхватывают изменения `settings.json`. Отдельно не проверялось.

## Прочие наблюдения

- По умолчанию у владельца `permission_mode: auto` — запросов разрешения будет мало, основная польза HUD: статусы, вопросы, «готово».
- У `SessionStart` нет `permission_mode`; `model` приходит строкой (`claude-haiku-5-5`).
- `Stop` содержит `last_assistant_message` — используем для итога.
- В `~/.claude/settings.json` уже есть хуки herdr, Orca и GSD, в том числе свой `PermissionRequest` от Orca (возвращает `{}`, решения не принимает). Установщик их не трогает; несколько хуков на одно событие Claude Code запускает параллельно.

## Технические решения

- **Сборка:** SwiftPM без Xcode-проекта (на машине только Command Line Tools), тесты на Swift Testing.
- **JSON:** свой парсер с сохранением порядка ключей и вида чисел (`JSONValue`), чтобы правка `settings.json` не перемешивала чужие настройки.
- **Сокет:** путь unix-сокета ограничен 104 байтами — тестовые сокеты держим по короткому пути.
- **Матчер `*`** для событий инструментов — как у уже установленных хуков пользователя.
- **Анимация через Core Animation, а не SwiftUI.** Первая версия рисовала персонажей в `Canvas` 24 раза в секунду — 12–15% CPU. Бесконечные SwiftUI-анимации (`repeatForever`) тоже тикают в нашем процессе с частотой экрана (120 Гц) — 6–7% даже без персонажей. Сейчас персонаж рисуется один раз на состояние, а покачивание, прыжки и пульс бейджа — `CABasicAnimation` на слое (`LayerMotion`), их считает рендер-сервер. Плюс модель публикует изменения только когда они есть. Итог: ~1% CPU при трёх анимированных агентах, 0% в покое. В меню есть выключатель анимации.
- **Задержка async-хука** при запущенном HUD: медиана 2,9 мс, p90 4,9 мс (30 запусков). HUD не запущен — хук выходит сразу.
- **Тесты без Xcode.** `swift test` в Command Line Tools не запускает Swift Testing, а у `_Testing_Foundation` нет модулей. Поэтому тесты — исполняемый таргет `agenthud-tests` с явной точкой входа и флагом `-disable-cross-import-overlays`.
- **Проверка UI без доступа к экрану.** У терминала нет разрешения на запись экрана, поэтому внешний вид проверяется снимком живого `NSHostingView` (`--render-previews`), а поведение — синтетическими событиями в настоящей панели (`--uitest`).
- **Первый запуск** сам предлагает подключить хуки (с показом изменений), кроме демо и тестового режима (`AGENTHUD_SOCKET`).

## Codex (добавлен 2026-11-16)

- Формат `~/.codex/hooks.json` совпадает с Claude Code; события: `SessionStart`, `UserPromptSubmit`, `PreToolUse`, `PermissionRequest`, `PostToolUse`, `SubagentStart/Stop`, `Stop`, `Interrupt`, `SessionEnd` (документация: https://learn.chatgpt.com/docs/hooks).
- `PermissionRequest` отвечается так же (`decision.behavior`), но **без** `updatedInput` — Codex с ним закрывает запрос с ошибкой.
- Хука для вопросов агента у Codex нет — вопросы Codex в HUD не попадают.
- `Interrupt` (пользователь прервал ход) → состояние «ждёт задачу», незаконченные шаги помечаются ошибкой.
- `SessionEnd` и `Interrupt` у Codex синхронные с лимитом 3 с — ставим без `async`, `timeout: 3`.
- **Доверие.** Codex запускает новые хуки только после проверки в `/hooks`; доверие хранится в `config.toml` по хэшу. Обходить это (флаг `--dangerously-bypass-hook-trust` или запись хэша за пользователя) не стали — пользователь подтверждает один раз сам.
- Живой прогон Codex не делали: без доверия хуки не запускаются. Адаптер проверен на событиях из документации (`Fixtures/codex/`) и в `--selftest`.
- У владельца `approval_policy = "never"` — запросов разрешения от Codex не будет; польза — статусы, шаги и «готово».

## Какие сессии попадают в HUD (обновлено: + десктоп)

Владелец работает в основном в десктопных приложениях, поэтому HUD показывает и их (`HostProbe.isInteractive`):

| Где | Как распознаём | В HUD |
|---|---|---|
| Терминал, Claude | `CLAUDE_CODE_ENTRYPOINT` = `cli` или нет, у процесса агента есть TTY | да |
| Приложение Claude | `CLAUDE_CODE_ENTRYPOINT=claude-desktop` и есть `CLAUDE_CODE_HOST_SESSION_ID` (`local_…`) | да |
| Служебные запросы приложения Claude | `claude-desktop` без id сессии | нет |
| SDK, `claude -p`, расширения редакторов | точка входа `sdk-*`, `claude-vscode` и т.п. | нет |
| Терминал, Codex | есть TTY | да |
| Приложение Codex | среди предков хука — `com.openai.codex` (это `/Applications/ChatGPT.app`) | да |
| `codex exec` из скрипта | ни TTY, ни приложения | нет |

Приложение-хост — самый внешний предок с `.app/Contents/MacOS/` в пути (`proc_pidpath`). Самый внешний, потому что Claude Code сам лежит в бандле `claude.app` внутри данных приложения.

**«Открыть» для приложений.** Форматы ссылок взяты из кода самих приложений:
- Claude: `claude://code/needs-input?session=<CLAUDE_CODE_HOST_SESSION_ID>` открывает конкретную сессию; проверено на живой сессии, в логе Claude ошибок нет.
- Codex: `codex://threads/<session_id>`; сопоставление `session_id` хука с id треда — по документации, вживую не проверено.

**Живая проверка в приложении Claude.** Вопрос `AskUserQuestion` из сессии в приложении Claude появился в окошке HUD, владелец ответил там, ответ дошёл до агента (`decisions.log`). Пока HUD держит вопрос, приложение Claude ждёт; кнопка «В приложении» отпускает вопрос туда.

## Живая проверка после установки

Claude Code в pty с установленными хуками: `SessionStart → UserPromptSubmit → PreToolUse → PermissionRequest (ждёт в HUD) → ответ в терминале → PostToolUse (HUD снял запрос) → Stop → SessionEnd` — по служебному логу `dev.agenthud`.

## Приложение Codex: служебные треды и вопросы (2026-11-16)

По живому логу приложения Codex:

- **Служебный тред.** После каждого ответа приложение запускает отдельный тред с соседним id (`thread-main` → `thread-helper`): `SessionStart → UserPromptSubmit («This is an app-generated request…») → Interrupt → SessionEnd`. В HUD он выглядел вторым диалогом в состоянии «Работает». Теперь адаптер помечает его как служебный (`internalSession`), хранилище удаляет его и игнорирует дальнейшие события. Тред Codex вообще появляется в HUD только после первого промпта — служебные не мигают.
- **`SessionEnd` для живого диалога.** Приложение присылает его, когда выгружает тред из памяти, а диалог в приложении остаётся. Для Codex в приложении `SessionEnd` больше не убирает сессию: остаётся последнее состояние, уберёт автоскрытие готовых. В терминале `SessionEnd` по-прежнему завершает сессию.
- **Вопрос `request_user_input_async`.** Инструмент выполняется мгновенно (19 мс), ход заканчивается, а ответ приходит следующим промптом. Если в ходе был такой вызов, после `Stop` состояние «Ждёт ответа» (а не «Готово») с текстом вопроса в окошке. Ответить из HUD нельзя: хуки Codex этого не поддерживают, кнопка ведёт в приложение.

## Панель в строке меню (2026-11-16)

Системное `NSMenu` заменено поповером на SwiftUI в стиле дизайн-системы Владилена (`vladilen-design-system/DESIGN.md` v1.0.0): нейтрали с фиолетовым оттенком, один акцент `#7C3AED` / `#A78BFA`, Golos Text, IBM Plex Mono для меток `01 / РАЗДЕЛ`, Spectral Light для заголовка. Шрифты (OFL) лежат в `Resources/Fonts`, регистрируются в процессе при запуске.

- Две вкладки: «Сессии» (список сессий, подключение агентов) и «Настройки» (вид, поведение). На одной странице панель была 1088 pt — выше экрана; теперь 554 и 710 pt.

## Стиль «Логотипы» (2026-11-16)

По просьбе владельца персонажи по умолчанию заменены иконками агентов: сразу видно, где Claude, где Codex. Иконки не рисуются и не кладутся в приложение — берутся у системы из установленных приложений (`NSWorkspace.icon(forFile:)` по bundle id `com.anthropic.claudefordesktop` и `com.openai.codex`). Если приложения нет, показывается нейтральная плашка с символом. Состояние передают бейдж, движение (Core Animation, 0% CPU в процессе) и насыщенность (простаивающий агент бледнеет). Капля, Бот и Пиксель остались в настройках; у тех, кто уже выбрал персонажа, стиль один раз переключён на логотипы.

## Codex auto-review: запрос разрешения не ждёт пользователя (2026-11-16)

Симптом: HUD показывал «Ждёт разрешения», а в Codex никакого подтверждения не было.

Причина: в треде включён `approval_policy: on-request` + `approvals_reviewer: auto_review`. Запросы на повышенные права (`sandbox_permissions: require_escalated`) решает встроенный ревьюер Codex. Хук `PermissionRequest` при этом вызывается, но Codex его не ждёт: по треду запросы решались за 17–31 с без ответа в HUD. Если ответить в HUD раньше, Codex принимает этот ответ: команда выполнилась через секунду после «Разрешить».

Что сделано:
- В событие хука Codex режим ревьюера не передаёт. Адаптер берёт последнее значение `"approvals_reviewer"` из файла треда (`transcript_path`, иначе `~/.codex/sessions/ГГГГ/ММ/ДД/rollout-*-<id>.jsonl`; поиск с конца через отображение в память).
- При `auto_review` запрос помечается `autoReview`. Он не считается ожиданием пользователя: нет «!», нет автооткрытия окошка, нет счётчика и уведомлений. В окошке написано «Codex проверяет запрос сам», кнопки «Разрешить» и «Отклонить» остаются.
- Если ревьюер отклонил команду, `PostToolUse` не придёт. Такой запрос снимается через 90 с, хук отпускается.
- Запрос снимается выполнением **той же команды** (сверяется текст команды). Раньше его снимало выполнение любой команды того же инструмента, а Codex выполняет команды параллельно.

## Форк 0.2.0

Форк [vladilenm/agent-hud](https://github.com/vladilenm/agent-hud) v0.1.1 под работу в VS Code. Прогон: 2026-11-20, macOS 15.7.2, Xcode (Swift 6.2.1), расширение Claude Code для VS Code 2.1.327.

### VS Code (отступление от SPEC, раздел 2)

Владелец форка работает в расширении Claude Code для VS Code, поэтому VS Code поддерживается — это главное отличие форка.

- **Как распознаём.** `CLAUDE_CODE_ENTRYPOINT=claude-vscode`, TTY нет, самое внешнее приложение в цепочке процессов — `com.microsoft.VSCode` (или Insiders). Цепочка на живой сессии: `zsh → …/anthropic.claude-code-2.1.327-darwin-arm64/resources/native-binary/claude → Code Helper (Plugin) → Code`. Без процесса VS Code в предках `claude-vscode` в HUD не попадает — так отсекаются Cursor и прочие форки редактора. `HostInfo.entrypoint` теперь передаётся в событии.
- **«Открыть».** Сначала окно с папкой проекта: папку берём из `~/.claude/ide/*.lock` (поля `workspaceFolders` и `pid`, токен не читаем; самый длинный префикс `cwd`, только живые `pid`), иначе — `cwd`. VS Code поднимает уже открытое окно с этой папкой. Через 0,45 с — ссылка `vscode://anthropic.claude-code/open?session=<session_id>`: VS Code отдаёт ссылку последнему активному окну. Ссылка описана в https://code.claude.com/docs/en/vs-code; в коде расширения 2.1.327 обработчик `/open` берёт `session` и `prompt`, уже открытую сессию делает активной.
- **Следующая задача.** Параметр `prompt` той же ссылки расширение вставляет в поле ввода (`setInputText`), но не отправляет — проверено по коду расширения. Поэтому HUD может предлагать быстрые промпты без риска отправить что-то за пользователя.
- **Встроенный терминал VS Code** (`TERM_PROGRAM=vscode`, есть TTY) остаётся терминальной сессией; «Открыть» поднимает окно проекта (вкладку терминала выбрать нельзя).

**Проверить вживую** (в документации не описано):
- не запускает ли расширение служебные сессии с той же точкой входа (как приложение Claude — там их отсекали по отсутствию id сессии);
- показывает ли VS Code свой запрос разрешения, пока ждёт хук `PermissionRequest`, и закрывает ли его ответ из HUD;
- вопрос `AskUserQuestion`: в терминале он не виден, пока его держит хук (P1), — ожидаем то же в VS Code; кнопка «В VS Code» отпускает его.

### «Всегда» (SPEC, раздел 12, п. 6)

- Документация хуков (`PermissionRequest decision control`, «Permission update entries»): в `allow` можно вернуть `updatedPermissions`, в том числе одну из `permission_suggestions` без изменений. Назначения: `session`, `localSettings` (`.claude/settings.local.json`), `projectSettings`, `userSettings` (`~/.claude/settings.json`).
- Подсказки Claude Code для `Bash` часто — точная одноразовая команда, и список правил `allow` разрастается до сотен записей. Поэтому HUD первым предлагает **шаблон** по первым словам: `npm run build` → `Bash(npm run *)`, `git status` → `Bash(git status *)`, `kill 41684` → `Bash(kill *)` (синтаксис с пробелом — его пишет сам Claude Code; `:*` тоже работает, но устарел). Шаблон не предлагается для составных команд (`&&`, `|`, `;`, перенаправления) — Claude Code проверяет их по частям, — для команд, которые выполняют произвольный код или опасны (`rm`, `sudo`, `node`, `python`, `curl`, `bash`…), и когда вторым словом идёт флаг.
- Для MCP-инструментов — правило на весь инструмент без `ruleContent` (документация: с `ruleContent` правило MCP ничего не совпадает).
- Режимы из подсказок показываются только безопасные (`acceptEdits`, `default`, `plan`); остальные из HUD не включаются.
- Для Codex «Всегда» не показывается: в ответе его хука таких правил нет, `allowWith` превращается в разовое `allow`.

### Одобрение плана (ExitPlanMode)

- Раньше `ExitPlanMode` хук пропускал. Теперь это отдельный запрос «План готов — одобрить?» с текстом плана (`tool_input.plan`).
- «Одобрить» — `allow` + `updatedInput` (вход как есть; документация требует его для ExitPlanMode) + `setMode: default` на сессию; «Одобрить и править сразу» — то же с `setMode: acceptEdits`; «Доработать…» — `deny` с замечаниями в `message`.
- **Проверить вживую** (в документации не описано): приходит ли `PermissionRequest` для ExitPlanMode во всех режимах; применяется ли `setMode` после одобрения плана; доходит ли `message` отказа до Claude как замечание к плану. Если хук для плана не придёт, ничего не сломается — HUD, как раньше, покажет «Агент ждёт ответа в VS Code» по `Notification`.

### Метки и цвета проектов

- Когда агент один (только Claude), иконки одинаковые — различать сессии приходится по проекту. Под иконкой — короткая метка: от имён отбрасывается общий для всех префикс из целых слов (`acme-mobile-app`, `acme-web-client` → `mobile`, `web`), совпадения уточняются следующими словами одновременно (`hrm-front`, `hrm-v2`).
- Безликие папки (`front`, `app`, `web`, `api`…) показываются с родительской: `acme-hrm/front` (SPEC, 4.4: «при коллизии — с родительской папкой»).
- Цвет проекта — стабильный оттенок из хэша `cwd`, один и тот же в HUD, панели и на карте.

### Журнал активности, сводка и карта агентов

- `~/Library/Application Support/AgentHUD/activity/ГГГГ-ММ-ДД.jsonl`: промпт (до 600 символов), конец хода (итог агента, счётчики инструментов, файлы правок, длительность), решения в HUD. Только локально, выключается в настройках. Пишутся события основного агента (без субагентов).

## Мерцание и рывки (0.2.1)

Жалоба после установки: «глюки в анимации и много моргания»; на скриншотах — огромный ввод (скрипт Workflow) выталкивает кнопки за нижний край, а HUD, перетащенный к левому краю, раскрывает окошко за экран.

**Замеры.** Инструментированная копия приложения (счётчики раскладки, перевешивания анимаций, `setFrame`) и живой лог двух сессий VS Code:
- Во время любой пружинной анимации (окошко открылось или закрылось, сессия появилась или пропала) содержимое HUD меняло размер на каждом кадре, и окно подстраивалось **~74 раза в секунду**, почти всегда с дробными размерами (198 из 254 замеров; хвост пружины 545,20 → 545,19 → 545,16…). Каждый раз содержимое заново выкладывалось — HUD мерцал.
- `LayerMotion` снимал и заново вешал анимацию на **каждой** раскладке: во время тех же анимаций иконки перевешивались до 170 раз в секунду — покачивание и подпрыгивание срывались в ноль и дёргались. В покое и при тиканье обратного отсчёта перевешиваний не было.
- Живой поток: 2,4 события в секунду, пики до 11; у одной сессии 23 запроса разрешения за 148 с и 32 смены состояния. Каждый запрос открывал окошко (пружина), ждущая сессия прыгала в начало ряда и обратно — иконки менялись местами.
- Запрос, на который ответили «No» в VS Code, или запрос субагента не снимался: `PostToolUse` той же команды не приходил, сессия часами (до конца хода или таймаута 10 мин) показывала «ждёт» с подпрыгиванием и мигающим «!». Позднее уведомление `permission_prompt` после `Stop` включало ложное «ждёт».
- Пульс «!» мигал бесконечно (непрозрачность 1 ↔ 0,45 каждые 0,6 с) — при нескольких ждущих сессиях угол экрана мигал постоянно.

**Что сделано.**
- Без пружинных анимаций раскладки в HUD: появление и исчезновение — только прозрачностью (`HUDFade`), окно подстраивается один раз. Размер округляется до целых точек, одинаковая рамка не переустанавливается. Содержимое прижато к углу-якорю, поэтому кадр расхождения окна и содержимого не сдвигает его к центру.
- `LayerMotion`: анимация перевешивается, только если слой её потерял; фаза покачивания — от общих часов (`MotionClock.epoch`), перевешивание не даёт рывка. Подпрыгивание — 4 повтора (~2,6 с), пульс — 3 вспышки, потом бейдж просто горит.
- Порядок иконок устойчивый (по времени появления). «+N» становится оранжевым, если ждёт кто-то из свёрнутых.
- Запросы: новый запрос того же агента снимает его прошлые (агент не спросит следующее, пока не ответили на предыдущее); `SubagentStop` снимает запросы субагента; `permission_prompt` учитывается только посреди хода.
- «Скрыть» действует до новой задачи или запроса (раньше сессия возвращалась на первом же событии — в VS Code через секунду). Сессия VS Code без задачи (открытая панель Claude) в HUD не показывается.
- Метки проектов считаются по устойчивому набору (все проекты за время работы + открытые окна VS Code), поэтому не меняются, когда сессии приходят и уходят. Общее первое слово отбрасывается только у «родни»: `agent-hub` остаётся `agent-hub`.
- Служебные вставки (`<task-notification>`, `<command-name>`…) не становятся заголовком сессии и не пишутся в журнал активности. Заголовок — по-прежнему первая настоящая задача: последний промпт часто оказывается коротким ответом на вопрос агента.
- Одна публикация модели на сообщение хука (раньше — на каждое событие), значок в строке меню перерисовывается только при смене числа ждущих.
- Окошко, открывшееся само на запрос, закрывается через 1 с после того, как запрос решён где угодно; следующий запрос в эту секунду его подхватывает — без мигания.

**Огромный ввод и перетаскивание.**
- Подробности запроса — в прокручиваемом блоке до 200 pt, текст обрезается по строкам и символам; для незнакомых инструментов (Workflow, MCP) — поля «ключ — значение» вместо сырого JSON. Окошко не выше экрана (видимая высота − 110 pt); сжимаются прокручиваемые части, запрос с кнопками раскладывается первым.
- Кнопки «Разрешить» / «Отклонить» (и «Одобрить», «Ответить») — крупные, на всю ширину, свой стиль: системная «выделенная» кнопка сереет в неактивном окне, а окошко, открытое запросом, неактивно.
- После перетаскивания (пауза 0,3 с) HUD определяет край по половине экрана: у левого якорь — левый верхний угол, окошко растёт вправо. Рамка прижимается к видимой части экрана (не за край и не на строку меню). Позиция по умолчанию — основной экран: `NSScreen.main` означает экран с фокусом, и при двух мониторах HUD без сохранённой позиции перепрыгивал между ними.

**VS Code показывает свой запрос параллельно** с ожиданием хука (скриншот владельца: «Do you want to…» в чате и то же окошко в HUD) — ответить можно в любом из двух мест.

**Регрессионные проверки** в `--uitest`: открытие и закрытие окошка — не больше 2 смен рамки (со старым кодом — 98), анимации иконок не перевешиваются при открытии окошка и появлении чужой сессии (со старым кодом — перевешиваются), окошко с огромным вводом не выше экрана и в его пределах, HUD у левого края раскрывается вправо, брошенный на строку меню возвращается на экран.
