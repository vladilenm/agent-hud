# AgentHUD — спецификация

Рабочее название: **AgentHUD**. Нативное macOS-приложение: маленький плавающий HUD в правом верхнем углу экрана, который показывает все запущенные в терминале сессии ИИ-агентов и позволяет отвечать им, не переключаясь в терминал.

> **Статус (2026-11-16):** v1 реализована по этой спецификации. Результаты проверок P1–P4 и отступления — в `DECISIONS.md`, установка и использование — в `README.md`.
>
> **Форк 0.2.0 (2026-11-20):** добавлены VS Code (вопреки разделу 2), «Разрешить всегда» и одобрение плана (раздел 12, п. 6), метки проектов, карта агентов и сводка за день. Подробности — `DECISIONS.md`, «Форк 0.2.0».

Документ написан для агента-разработчика. Пометки:
- **[решено]** — делать именно так;
- **[предложено]** — разумное решение по умолчанию; менять можно, если в ходе работы найдётся причина (зафиксировать её в `DECISIONS.md`);
- **[проверить]** — техническая деталь, которую агент проверяет сам на прототипе и записывает вывод в `DECISIONS.md`. Решения владельца для этого не нужны.

## 1. Проблема и цель

Агенты (Claude Code, Codex, Pi) работают в окнах терминала. Пока окна свёрнуты или закрыты другими, не видно, кто работает, кто ждёт разрешения, кто задал вопрос, кто закончил. Приходится весь день переключаться между окнами.

**Цель:** один взгляд в угол экрана отвечает на вопрос «что сейчас с моими агентами», а самые частые действия (разрешить, ответить, перейти в сессию) делаются прямо из HUD.

## 2. Охват

| | v1 | Позже |
|---|---|---|
| Агенты | **Claude Code** | Codex, Pi, другие — через адаптеры (раздел 4.5) |
| Где запущены агенты | **Терминал** (на машине установлен только Terminal.app) | Другие терминалы по запросу |
| Десктопные приложения Claude и Codex | **Поддерживаем** [решено владельцем 2026-11-16, см. DECISIONS.md] | — |
| VS Code, Cursor | **Не поддерживаем и не трогаем** [решено] | — |

Архитектура v1 с первого дня строится так, чтобы новый агент подключался отдельным адаптером без переделки UI и ядра [решено].

## 3. Пользовательские сценарии (v1)

1. **Видеть всех агентов.** В правом верхнем углу ряд «маленьких друзей» — по одному на каждую активную сессию. По виду персонажа понятно состояние: работает / ждёт меня / закончил / ошибка / просрочено.
2. **Посмотреть, что делает агент.** Клик по персонажу раскрывает маленькое окошко: проект, первый промпт сессии, лента шагов (вызовы инструментов с краткой сутью: «Read src/app.ts», «Bash: npm test», «Edit 3 файла»), текущий шаг, время работы.
3. **Разрешить действие.** Агент запросил разрешение (например, на `Bash`) — персонаж сигналит, в окошке видно, что именно агент хочет сделать, и кнопки **«Разрешить»** и **«Отклонить»**.
4. **Ответить на вопрос.** Агент вызвал `AskUserQuestion` — в окошке тот же вопрос с вариантами (одиночный и множественный выбор плюс свой текст). Ответ уходит агенту, агент продолжает.
5. **Перейти в сессию.** Кнопка **«Открыть»** выводит на передний план окно и вкладку терминала, где идёт эта сессия.
6. **Узнать, что агент закончил.** Персонаж показывает «готово», кнопка ведёт в сессию. Готовая сессия гасится через настраиваемое время или по клику «Скрыть».
7. **Увидеть просроченное.** Если на разрешение или вопрос не ответили до истечения времени хука, окошко показывает «Просрочено» и предлагает «Открыть» — ответить уже в терминале.

Вне v1 (раздел 12): Codex и Pi, подтверждение плана (`ExitPlanMode`), «Разрешить всегда», отправка нового промпта из HUD, удалённое управление с телефона.

## 4. Архитектура

```
┌──────────────────────┐   stdin JSON    ┌──────────────────┐  unix socket  ┌─────────────────────┐
│ Claude Code          │ ──────────────▶ │ agenthud-hook    │ ────────────▶ │ AgentHUD.app        │
│ (в Terminal.app)     │ ◀────────────── │ (CLI, Swift)     │ ◀──────────── │ (SwiftUI, menu bar, │
└──────────────────────┘  stdout JSON    └──────────────────┘   ответ       │  плавающая панель)  │
                                                                            └─────────────────────┘
                                            transcript_path (только чтение) ──────▲
```

### 4.1. Компоненты

| Компонент | Что делает | Статус |
|---|---|---|
| `AgentHUD.app` | Приложение в строке меню (без иконки в Dock) + плавающая панель HUD. Держит состояние всех сессий, рисует UI, передаёт решения пользователя. | **[решено]** Swift 6 + SwiftUI, панель на `NSPanel` (`.nonactivatingPanel`, `.floating`, видна на всех Spaces и поверх полноэкранных окон). Минимум macOS 15. |
| `agenthud-hook` | Маленький CLI, который агент вызывает как `command`-хук. Читает JSON из stdin, добавляет контекст окружения, шлёт в приложение, при необходимости ждёт ответа и печатает JSON-решение в stdout. Первый аргумент — имя адаптера и тип события: `agenthud-hook claude permission`. | **[решено]** Swift, тот же репозиторий, кладётся в `.app` (`Contents/Helpers/`) и симлинкуется в `~/.local/bin/` |
| Транспорт | Unix domain socket `~/Library/Application Support/AgentHUD/hud.sock`, права `0600`. Формат — одна JSON-строка на сообщение (NDJSON). | **[предложено]** Не `http`-хук: при выключенном приложении `http`-хук даёт ошибку подключения в логе сессии, а `command`-хук может молча выйти. |
| Установщик хуков | Пункт меню «Подключить Claude Code» / «Отключить». Пишет блок хуков в `~/.claude/settings.json`. | **[решено]** |

### 4.2. Подписка на события Claude Code

| Событие | Режим хука | Зачем |
|---|---|---|
| `SessionStart` | async | Создать сессию: `session_id`, `cwd`, `transcript_path`, `model`, источник (`startup`/`resume`/…) |
| `UserPromptSubmit` | async | Состояние «работает», первый/последний промпт (`prompt`) как заголовок |
| `PreToolUse` (matcher `.*`) | async | Шаг в ленте: «начал инструмент X с такими аргументами» |
| `PreToolUse` (matcher `AskUserQuestion`) | **синхронный, ждёт ответа** | Показать вопрос, вернуть ответ через `updatedInput` (5.3) |
| `PermissionRequest` (matcher `.*`) | **синхронный, ждёт ответа** | Показать запрос разрешения, вернуть `allow`/`deny` (5.2) |
| `PostToolUse` (matcher `.*`) | async | Шаг завершён, длительность `duration_ms` |
| `Notification` | async | `permission_prompt`, `idle_prompt`, `agent_needs_input`, `agent_completed` — подстраховка статусов |
| `SubagentStart` / `SubagentStop` | async | Вложенные субагенты в ленте шагов (не отдельными персонажами) |
| `Stop` | async | Состояние «готово», итог из `last_assistant_message` |
| `SessionEnd` | async | Убрать персонажа (с короткой анимацией) |

Async-хуки помечаются `"async": true` и не задерживают агента. Синхронные получают увеличенный `timeout` (**[предложено]** 600 с, настраивается в приложении).

Точные поля входного JSON сверить с актуальной документацией: https://code.claude.com/docs/en/hooks (общие поля: `session_id`, `transcript_path`, `cwd`, `permission_mode`, `hook_event_name`, `agent_id`/`agent_type` внутри субагента).

### 4.3. Контекст окружения, который добавляет `agenthud-hook`

Нужен для кнопки «Открыть» и подписи персонажа:
- `TERM_PROGRAM`, `TERM_SESSION_ID` и прочие переменные терминала;
- TTY процесса агента (`ps -o tty= -p <ppid>` или `ttyname`);
- PID процесса агента и цепочка родителей до GUI-приложения;
- признаки мультиплексора: переменные `HERDR_*` / `ORCA_*` (на машине установлен herdr — см. 5.4).

### 4.4. Модель данных (в памяти приложения)

```swift
enum AgentKind { case claudeCode /* позже: codex, pi */ }
enum AgentState { case starting, working, waitingPermission, waitingAnswer, expired, idle, done, error, ended }

struct AgentSession {
  let id: String               // "<kind>:<session_id>"
  let kind: AgentKind
  var cwd: URL
  var projectName: String      // basename(cwd); при коллизии — с родительской папкой
  var title: String            // первый промпт, обрезанный до ~60 символов
  var host: TerminalHost       // terminal.app / herdr / unknown + pid, tty
  var state: AgentState
  var steps: [Step]            // последние 200, старые выкидывать
  var pending: [PendingRequest] // очередь разрешений/вопросов, показывается первый
  var startedAt, lastEventAt: Date
  var lastMessage: String?     // из Stop.last_assistant_message
  let avatarSeed: UInt64       // хэш id → внешний вид персонажа
}

struct Step { id, toolName, summary, startedAt, durationMs?, status: running|ok|failed, agentId? }
struct PendingRequest { requestId, type: permission|question, payload, createdAt, deadline, status: open|answered|expired|answeredElsewhere }
```

- Сессия без событий дольше **[предложено]** 30 мин и без живого PID → `ended`.
- Состояние только в памяти. **[предложено]** Плюс журнал решений `~/Library/Application Support/AgentHUD/decisions.log` (что разрешено/отклонено/отвечено/просрочено и когда).
- Если HUD запущен позже сессии — ленту шагов подтянуть из `transcript_path` (только чтение, JSONL). **[предложено]** Если формат транскрипта нестабилен — показывать только события с момента запуска HUD.

### 4.5. Адаптеры агентов [решено: интерфейс в v1, реализации Codex/Pi — позже]

Ядро приложения не знает про конкретного агента. Каждый адаптер:
1. переводит события своего агента в общие внутренние события: `sessionStarted`, `promptSubmitted`, `toolStarted`, `toolFinished`, `permissionRequested`, `questionAsked`, `stopped`, `sessionEnded`, `notification`;
2. переводит ответ пользователя (разрешить / отклонить / ответ на вопрос / «нет ответа») обратно в формат своего агента;
3. умеет установить и удалить свою интеграцию в конфиг агента.

В v1 — только `ClaudeCodeAdapter`. Ориентиры на будущее (не реализовывать в v1, но не мешать им):
- **Codex** (`codex-cli` 0.153): есть `~/.codex/hooks.json` с событиями в духе Claude Code, включая `permission_request`, `pre_tool_use`, `stop`.
- **Pi** (1.4.0): расширения на TypeScript в `~/.pi/agent/extensions/`.
- Готовые интеграции herdr (`herdr integration status`) для этих агентов — хороший образец, как они отдают состояние.

## 5. Ключевые потоки

### 5.1. Обычный шаг (async)
`agenthud-hook` получает событие → подключается к сокету с таймаутом 200 мс → отправляет `{type:"event", ...}` → выходит с кодом 0 и пустым stdout. Не удалось подключиться — тоже код 0, пусто.

### 5.2. Запрос разрешения (`PermissionRequest`)
1. Хук отправляет `{type:"permission_request", request_id, session_id, tool_name, tool_input, permission_suggestions, env, deadline}` и ждёт ответа на том же соединении.
2. HUD показывает маленькое окошко: что агент хочет сделать (для `Bash` — команда и `description`; для `Edit`/`Write` — путь и короткое превью изменений; для MCP — сервер, инструмент, аргументы), кнопки **Разрешить** / **Отклонить** (необязательное поле «почему» уходит в `message`) и **Открыть** (перейти в терминал).
3. Ответ → хук печатает:
   ```json
   {"hookSpecificOutput":{"hookEventName":"PermissionRequest","decision":{"behavior":"allow"}}}
   ```
   или `{"behavior":"deny","message":"<текст пользователя или 'Отклонено в AgentHUD'>"}`.
4. HUD закрыт или упал, соединение порвалось → хук печатает пустой вывод, код 0: агент спрашивает в терминале как обычно.
5. Пользователь ответил в самом терминале → окошко в HUD снимается (статус `answeredElsewhere`): по завершению процесса хука или по следующему событию этой сессии (`PostToolUse`, `Stop`, новый `PreToolUse`).
6. **[проверить]** Показывает ли Claude Code свой диалог в терминале одновременно с ожиданием хука. Если нет — добавить в окошко кнопку «Ответить в терминале», которая отпускает хук без решения и открывает сессию.

### 5.3. Вопрос агента (`AskUserQuestion`)
1. `PreToolUse` с matcher `AskUserQuestion` отправляет `{type:"question", request_id, session_id, tool_input:{questions:[...]}, deadline}` и ждёт.
2. HUD рисует все вопросы: `header` как чип, `question`, варианты с `description`, `multiSelect`, поле «Свой ответ».
3. Ответ → хук печатает:
   ```json
   {"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"allow",
     "updatedInput":{"questions":[...исходный массив без изменений...],
                     "answers":{"<текст вопроса>":"<label>", "<вопрос 2>":"<label1>, <label2>"}}}}
   ```
   Множественный выбор — метки через запятую, свой текст — строкой. Просто `allow` без `answers` **не работает** (так сказано в документации).
4. Нет ответа / HUD не запущен → пустой вывод, вопрос задаётся в терминале.

### 5.4. Кнопка «Открыть»
Порядок попыток **[предложено]**:
1. Сессия внутри herdr (есть `HERDR_*` в окружении хука) → `herdr agent focus <id>` / `herdr pane …` для нужной панели, затем активировать окно терминала, в котором открыт herdr. **[проверить]** точные переменные и команду.
2. Сессия в Terminal.app → AppleScript: найти окно и вкладку по TTY (`tty of tab`), выбрать вкладку, поднять окно, активировать Terminal.
3. Не удалось определить → просто активировать Terminal.app.

Первая попытка AppleScript вызовет системный запрос «AgentHUD хочет управлять Terminal» — описать в README.

### 5.5. Просрочка
1. У каждого ожидающего запроса есть `deadline` = время создания + `timeout` хука минус запас 5 с.
2. Хук сам отпускает ожидание за 5 с до своего `timeout` и печатает пустой вывод — чтобы Claude Code не убил его и не записал ошибку, а спросил пользователя в терминале.
3. HUD переводит запрос в `expired`: персонаж — серо-оранжевый с часами, в окошке «Просрочено — ответьте в терминале» и кнопка **Открыть**. Кнопки «Разрешить/Отклонить» неактивны.
4. Просроченное окошко снимается, когда сессия пошла дальше (следующее событие) или по «Скрыть».

## 6. UI

### 6.1. Свёрнутый HUD
- Правый верхний угол основного экрана, под строкой меню. Горизонтальный ряд персонажей 32–40 pt, полупрозрачная подложка (`.ultraThinMaterial`), скруглённые углы.
- Персонаж — **оригинальный** процедурный «маленький друг»: форма + цвет + глаза из `avatarSeed`, у каждой сессии свой и стабильный. Чужих персонажей не копировать. **[предложено]** Агент делает 2–3 варианта стиля и показывает владельцу до финальной полировки.
- Анимация по состоянию **[предложено]**:
  - `working` — лёгкое покачивание, моргание;
  - `waitingPermission` / `waitingAnswer` — подпрыгивает, оранжевый бейдж «!»;
  - `expired` — замирает, бейдж с часами;
  - `done` — зелёная галочка, спокойный;
  - `error` — красный бейдж;
  - `idle` — серый, «спит».
- Наведение → тултип: проект, заголовок, текущий шаг.
- Больше ~6 персонажей — сворачивать в «+N».
- HUD можно перетащить; позиция запоминается. Режим «прятать, когда никто не ждёт».

### 6.2. Окошко сессии (по клику)
- Маленькое: ширина ~360 pt, высота по содержимому, максимум ~480 pt со скроллом ленты.
- Шапка: персонаж, проект, заголовок, где запущено («Terminal · agent-management»), время работы, кнопки **Открыть** и **Скрыть**.
- Если есть ожидающий запрос — он сверху, крупно, с кнопками действий.
- Ниже — лента шагов: иконка инструмента, краткая суть, длительность, статус. Субагенты — с отступом.
- Для `done` — последний ответ агента (обрезанный, «Показать целиком»).
- Клавиатура: `⌘↩` разрешить, `⎋` закрыть, `1…9` выбор варианта. Фокус клавиатуры окошко берёт только когда открыто; свёрнутый HUD фокус у терминала не крадёт.

### 6.3. Строка меню
Иконка со счётчиком ожидающих. Меню: список сессий, «Подключить Claude Code» / «Отключить», «Настройки», «Журнал решений», «Выход».

### 6.4. Уведомления
**[предложено]** Системное уведомление macOS, когда сессия ждёт разрешения или ответа дольше 10 с, а HUD скрыт. Звук по умолчанию выключен.

## 7. Установка хуков

- «Подключить Claude Code»:
  1. Бэкап `~/.claude/settings.json` → `settings.json.agenthud-backup-<timestamp>`.
  2. Добавить хуки AgentHUD в массивы соответствующих событий, **не трогая чужие записи**. У пользователя уже есть хуки herdr (`~/.claude/hooks/herdr-agent-state.sh`) и плагинов — они должны продолжить работать. Свои записи узнаваемы по полному пути к `agenthud-hook`.
  3. Показать дифф, проверить итоговый JSON, записать атомарно (temp-файл + rename).
- «Отключить» удаляет только записи AgentHUD.
- Уже открытые сессии подхватывают новые хуки сами [решено владельцем; при разработке убедиться, что это так].

Пример записи (ориентир, сверить с документацией):
```json
{
  "hooks": {
    "PermissionRequest": [
      { "matcher": ".*", "hooks": [ { "type": "command", "command": "/Users/<user>/.local/bin/agenthud-hook claude permission", "timeout": 600 } ] }
    ],
    "PreToolUse": [
      { "matcher": "AskUserQuestion", "hooks": [ { "type": "command", "command": "/Users/<user>/.local/bin/agenthud-hook claude question", "timeout": 600 } ] },
      { "matcher": ".*", "hooks": [ { "type": "command", "command": "/Users/<user>/.local/bin/agenthud-hook claude event", "async": true } ] }
    ]
  }
}
```

## 8. Безопасность

- Сокет — локальный файл с правами `0600` в каталоге пользователя; приложение проверяет UID подключившегося процесса (`getpeereid`).
- HUD никогда не одобряет сам; «Разрешить» действует на один конкретный `request_id`.
- Ответ на устаревший или просроченный запрос игнорируется.
- Аргументы инструментов показываются как текст, без исполнения и без рендера ссылок.
- `agenthud-hook` ничего не пишет в stdout, кроме итогового JSON решения, и никогда не выходит с кодом 2. Если HUD не запущен — агент работает так, будто AgentHUD нет.
- Никаких сетевых запросов наружу и телеметрии.

## 9. Требования к качеству

- Async-хук добавляет к работе агента не больше ~50 мс (замерить).
- Приложение в простое: < 1% CPU, < 80 МБ RAM.
- Нормально работает с 10+ параллельными сессиями.
- Неизвестное событие или новые поля не роняют ни хук, ни приложение — логируются и игнорируются.
- Тесты:
  - юнит: разбор каждого события (JSON-фикстуры), построение ответа хука (разрешение, отказ с причиной, вопрос с одиночным/множественным/своим ответом, пустой вывод при отсутствии HUD и при просрочке), слияние и удаление хуков в `settings.json` (файл с чужими хуками herdr и плагинов), расчёт `deadline`;
  - интеграционный: фейковый агент (скрипт) вызывает `agenthud-hook` с фикстурами, проверяется stdout и состояние приложения;
  - ручной прогон по чек-листу из раздела 13 на живом Claude Code в Terminal.app.

## 11. Что агент проверяет сам на прототипе (до основной разработки)

Короткие проверки, вывод — в `DECISIONS.md`:
- **P1.** Показывает ли Claude Code диалог разрешения/вопроса в терминале, пока синхронный хук ждёт, и что происходит с процессом хука, если ответить в терминале (5.2, п. 6).
- **P2.** Что делает Claude Code, если синхронный хук превысил `timeout` и если хук сам вышел с пустым выводом незадолго до него (5.5).
- **P3.** Поиск вкладки Terminal.app по TTY через AppleScript; переменные окружения и команда фокуса для сессий внутри herdr (5.4).
- **P4.** Подхват изменённого `settings.json` уже открытой сессией.

## 12. Этапы

1. **Проверки P1–P4** → `DECISIONS.md`.
2. **Каркас:** SwiftPM-пакет, приложение в строке меню, сокет-сервер, `agenthud-hook`, интерфейс адаптера и `ClaudeCodeAdapter`, установщик хуков. Критерий: в логе приложения видны все события живой сессии Claude Code.
3. **HUD только для чтения:** персонажи, состояния, окошко с лентой шагов, «Скрыть», «Открыть».
4. **Интерактив:** разрешения, вопросы, просрочка, снятие окошка при ответе в терминале, журнал решений.
5. **Полировка:** 2–3 варианта персонажей на выбор владельцу, анимации, клавиатура, уведомления, настройки (позиция, автоскрытие, таймаут), README с установкой и удалением.
6. **Следующие версии (по решению владельца):** адаптеры Codex и Pi; `ExitPlanMode`; «Разрешить всегда» через `permission_suggestions` → `updatedPermissions`.

Не делать без отдельного решения владельца: поддержку VS Code/Cursor, отправку новых промптов из HUD, доступ по сети или с телефона, автоодобрение по правилам.
